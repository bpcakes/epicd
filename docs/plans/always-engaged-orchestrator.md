# Give the persistent orchestrator control of delivery

This ExecPlan is a living document. Keep `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` current as implementation proceeds. It is based on repository revision `7a0ba49`, inspected on 2026-09-05. No applicable `AGENTS.md` or `PLANS.md` was found in this repository or its parent instruction paths. This document specifies future work; it does not claim that the architecture below already exists.

## Purpose / Big Picture

Epicd should be a persistent engineering lead: it understands a Beads epic, assigns implementation and independent review, investigates failures, changes tactics, and delivers verified local commits. The orchestrator is `gpt-6-astra` and chooses the work. A small deterministic safety kernel owns authority, records evidence, and rejects actions that violate the delivery contract. This model requirement applies to adaptive orchestration in both SDK and native Herdr modes; implementation, review, and specialist models remain separately configurable.

After this change, a failed browser test can lead to a diagnostic conversation, inspection of a declared local fixture, authorized fixture creation, and successful revalidation within the same run. A verifier that generates tracked receipts loses eligibility to approve that attempt; the orchestrator can inspect the receipts, preserve evidence, replace its workspace, and continue. Neither incident is automatically a terminal run failure. These behaviors must work with direct SDK sessions and Herdr-managed Codex agents.

The central distinction is between **delivery strategy**, which the model chooses, and **operation correctness**, which code enforces. Claim, implement, review, commit, verify, and close remain visible activities and prerequisite relationships. They no longer select the next operation. The model may insert inspection, diagnosis, replacement, validation, or waiting at any point. It cannot remove the proof required to publish a commit or close a task.

## Surprises & Discoveries

Commit implementation exposed two additional identity requirements. A successful pre-commit check must not be superseded merely because the same check starts at the actual commit SHA; latest-check lookup now keys by candidate, check, phase, and revision. Likewise, a pre-commit reviewer cannot be reused for actual-SHA verification: `run_review` derives `review` versus `verification` assignment purpose from the registered immutable workspace and supplies phase-specific evidence IDs. Old pre-commit prompt hashes remain valid because the new phase field is checked when present, while its historical absence is accepted only for pre-commit records.

The original file scanner combined baseline tracked paths with untracked paths. A newly staged path could disappear from that untracked listing even though its source bytes changed after approval. It now also enumerates cached paths and still reads actual bytes, never staged blob content. The new staged-file contamination test fails commit admission; the positive commit test keeps the old index byte-for-byte unchanged while a separate kernel-built index supplies the approved tree.

A post-commit repair cannot start from the previous assignment's unchanged HEAD and produce a sibling commit. The commit journal now checks the latest retained private parent, and `create_implementation_workspace` creates a new writable copy from that commit without resetting the old workspace. Tests append and independently verify a repair commit after an actual-SHA finding. Publication will still need to reconcile this private application lineage with its authoritative delivery tip and proven tracker-only descendants.

Review evidence exposed two durable-state traps. Adding a default `reviewContext: null` would change the digest of historical prompts, so the new field is optional and absent on old serialized turns; schema-seven migration tests assert byte-for-byte preservation. Sticky reviewer check requirements also need admission: a reviewer changing an existing command under the same ID would otherwise make every later plan fail. Reject that report as approval/requirements evidence, preserve its valid candidate-bound findings and raw turn, and require a corrected independent review with a new command ID.

Large finding sets cannot simply be omitted or rejected forever. The review journal now supplies a bounded batch with an explicit omitted count, accepts resolutions only for IDs actually supplied to that turn, and keeps every unsupplied finding open. The coordinator can request additional review turns. Oversized reports remain readable through character-offset `read_review` pages; `inspect_findings` pages the durable task ledger. Full approval still requires an empty unresolved ledger, not merely completion of the current batch.

Durable native integration, 2026-09-07: Herdr 0.8.2 omits an unregistered agent's `name`; it also reports `interactive_ready` only for a managed `agent.start`, not an arbitrary native process launched with `pane run`. The first probes exposed both assumptions and were stopped rather than counted as success. The driver now installs a private POSIX startup function in its owned terminal, verifies the exact setup marker outside agent access, and uses managed `agent.start`. That function executes the one-use launcher with `exec`, replacing the host shell instead of leaving a shell waiting for a delayed prompt. The next turn gets another owned terminal but resumes the same private provider conversation. The readiness guard remains strict. This follows the inspected 0.8.2 implementation, not an inference from the optional JSON fields. [Herdr managed launch and readiness](https://github.com/herdrdev/herdr/blob/v0.8.2/src/app/agents.rs).

Codex 0.153.4 creates the private `state_5.sqlite` thread identity before filling in its model and reasoning metadata. The pinned reader accepts provisional identity for correlation but never invents the missing settings: result admission still requires the eventual exact model and effort. It rejects ambiguous sessions, unsupported versions, wrong workspace/settings, shared files, and aliases. The complete accepted prompt must also appear under that exact session in private `history.jsonl`; terminal text and the model's own result file cannot acknowledge delivery. This private-format dependency is explicit and version-gated, not a supported public Codex API. The runtime's command policy keeps those files outside agent tools' access.

Herdr lifecycle changes can settle to idle before a result exists. The native driver continues observing the same submission until the exact acknowledged turn has a valid result and matching provider metadata, or its deadline/authority expires; it does not resend. `agent read` returns bounded plain text, not a JSON result envelope, so diagnostics are labeled incomplete and the occupant is checked before and after reading. Large coordinator prompts go through the documented newline-delimited socket `agent.prompt` request instead of a single OS argument. Responses must match both request ID and exact terminal identity, and the server socket incarnation is checked before and after delivery. Lost acknowledgement remains uncertain and is not retried. [Herdr socket protocol](https://herdr.dev/docs/socket-api/).

Durable SDK integration, 2026-09-07: A real coordinator request rejected Zod's `oneOf` action schema even though scripted transport tests passed. The transport now uses an equivalent nested `anyOf` over the same distinct literal-kind action variants; the kernel still validates the original discriminated schema and refinements. The existing output-shape normalizer is shared with worker schemas. Official guidance documents the supported nested union form and strict required fields. [Structured Outputs schema support](https://developers.openai.com/api/docs/guides/structured-outputs#supported-schemas).

The same failed request exposed an SDK 0.153.4 cleanup race: its iterator removes child-process error listeners, so aborting its spawn signal afterward can raise an uncaught `AbortError` in the controller. The durable driver no longer delegates process ownership to that signal. It races its own stream consumption against cancellation, requests interruption through the exact-generation supervisor, and retains workspace ownership until a trusted receipt exists. Late observations must still pass current turn/lease checks. Ordinary provider binding and turn completion now append observations without incrementing the control version; otherwise the coordinator invalidates its own decision ticket.

Private durable control paths exceed Linux's pathname-socket length limit. Both the client and supervisor now hold a checked directory descriptor and address `control.sock` through `/proc/self/fd/<fd>`, retaining private filesystem ownership rather than moving to an exposed abstract socket. A prepared-but-unstarted launch can be prevented by atomically claiming its start gate; an unknown active launch cannot be treated as absent just because its socket is not listening yet.

Confined native launch, 2026-09-07: Authentication through `CODEX_ACCESS_TOKEN` did not reach the inspected exec requests (401), and `login --with-access-token` rejected the managed token's identity format. A private cache projection containing the existing access token, identity token, account ID, and unchanged refresh timestamp authenticated successfully. It deliberately excludes the real refresh token. The original cache is read only through a bounded, no-follow, owner-only file check; the projection stays outside local-command access. This is not an implemented refresh lifecycle: expired credentials require the existing credential owner to refresh and a safely stopped invocation to be reseeded. Never forge refresh timestamps or create competing refresh-token owners. The official CI guidance likewise requires one owner for a reusable managed cache. [Managed authentication](https://learn.chatgpt.com/docs/auth), [cache ownership and refresh](https://learn.chatgpt.com/docs/auth/ci-cd-auth).

Command-profile prototype, 2026-09-07: `src/adapters/codex-confinement.ts` creates a once-only private configuration using named permissions, an untrusted project declaration, protected metadata, separate tool scratch/results, and disabled command networking. The selected native executable needs an exact read grant because Codex re-executes it inside its command sandbox. Test provider homes use `/var/tmp` because the inspected executable refuses helper creation under `/tmp`. No real credentials are copied into these fixtures.

The `:tmpdir` special path resolves to the configured tool `TMPDIR`, which is private scratch here. Denying it overrides an explicit write grant for the same directory. The prototype grants that private temporary directory while denying `/tmp`. Another probe initially read host-path aliases only after trying to write them: Bubblewrap's synthetic parent directories allowed ephemeral files at the same pathname while the real host file stayed unchanged. The corrected test reads before attempting writes and checks actual host bytes afterward; protected source/metadata writes must still fail, and declared scratch/result writes must succeed. CLI exit zero alone is insufficient: the probe requires a result file produced by the executed command. These findings establish neither unrestricted host access nor complete agent confinement.

Delivery integration, 2026-09-07: Checking only the source agent's latest turn misses another implementation assignment for the same task. Candidate eligibility now records the task's writer-turn count and rejects a candidate while any task writer has an unknown stop state or after another writer turn was prepared. Historical validation remains inspectable; a later failed retry or a changed plan/candidate cannot be hidden by selecting an older passing result.

Validation records distinguish a failed command from `not_started` admission failure. A read-only copy that has been contaminated is preserved and never presented as having passed a command. Output truncation likewise cannot satisfy a required check. The supervisor's omission marker makes retained text slightly larger than its nominal 64 KiB buffer, and JSON escaping can expand binary diagnostics again; the evidence schema and inspection bounds account for both effects.

Workspace implementation, 2026-09-07: Before/after file fingerprints do not exclude a writer starting between asynchronous capture steps. Workspace I/O now acquires a SQLite exclusion in the same transaction boundary used by agent admission. Only settled trusted I/O releases it; replacing the controller lease does not. Cross-controller stop reconciliation is still required before an abandoned exclusion can be released. Likewise, a reserved checkout is not ready merely because its tracked files match: recovery must reject unexpected ignored files and preserve missing or contaminated copies.

The physical copy uses local Git object copying with `--no-hardlinks`, no checkout, and an empty template, then installs a fixed private configuration before reading copied objects. Blob materialization and capture bypass filters and the normal index. It supports SHA-1 and SHA-256 repositories, linked source worktrees, binary bytes, executable modes, and symlink contents. Submodules, partial/shared source object stores, and filter/encoding materialization remain unsupported. The current bounds are 64 MiB per file, 512 MiB of candidate contents, and 100,000 materialized namespace entries. These are implementation limits, not silently truncated copies. The copy is separate storage; runtime confinement must still make review source immutable during execution. [Local copy options](https://git-scm.com/docs/git-clone), [raw blob hashing](https://git-scm.com/docs/git-hash-object).

Agent coordination implementation, 2026-09-07: A fresh SDK thread has no provider session ID until its `thread.started` event, whereas native Herdr identity is available before prompt submission. The journal persists the SDK instance, assignment, exact prompt, and dispatch intent first, then binds the start event to that exact turn. Known provider sessions cannot be shared across SDK/Herdr instances. Herdr's initially unknown provider session may be filled in only without changing its name/pane/tab/terminal identity.

Mailbox reservation and prompt acknowledgement are separate records. Cancellation before dispatch returns reserved messages to the queue; uncertain submission does not. A stopped turn without a correlated acknowledgement leaves its messages visibly indeterminate. Stop requests remain irreversible across an indeterminate/restart transition, so a later successful agent result cannot regain eligibility. Revocation preserves the old assignment and messages, invalidates its result claims, and quarantines its workspace; it does not prove that a process stopped or transfer uncertain instructions to a replacement.

Model-guidance recheck, 2026-09-07: The adaptive resolver, frozen policy, and StateStore creation/settings paths enforce Astra. The CLI/TUI and legacy engine still use their existing resolver; their adaptive wiring remains Milestone 6 work. The earlier `OrchestratorLoop.run()` treated every decision-source exception as a rejected decision and immediately tried another ticket, consuming the delivery budget without a functioning coordinator. The implementation now uses `DecisionJournal` and a bounded source-recovery path. Healthy coordinator feedback for a failed worker remains distinct from coordinator unavailability. Actual runtime error normalization and provider-identity/stop reconciliation still need their live adapters.

Native-runtime inspection, 2026-09-07: `codex --version` initially reported 0.153.4 while the pinned TypeScript SDK package was 0.151.0. Both are now 0.153.4 but remain separate launch selections. The SDK's `CodexExec.run()` adds `--sandbox` whenever `ThreadOptions.sandboxMode` is supplied. Current permission-profile documentation says that flag selects the older sandbox configuration instead of a named permission profile. Therefore adding profile overrides to the current adapter is not an isolation implementation. Profiles govern local commands, while MCP, apps, browser tools, and service traffic have separate controls. Preserve the admission failure until the complete selected launch profile is demonstrated. [Permission profiles and precedence](https://learn.chatgpt.com/docs/permissions), [separate command and service boundaries](https://learn.chatgpt.com/docs/agent-approvals-security).

The journal checks both in the same SQLite transaction as each mutation. SQLite-only capabilities commit their effect and terminal result together. External handler errors are indeterminate unless the provider supplies a definitive failed-and-stopped result; reconciliation inspects an earlier effect instead of re-executing it. Unknown capabilities return an auditable rejection and do not block the run.

The installed Herdr protocol's field is `agent_status`, not the `state` field previously used by test fixtures. `HerdrObserver` now validates pane, tab, terminal, and available provider session identity. A ready lifecycle is not a process-stop acknowledgement. Existing legacy Herdr turns now poll bounded `agent get` calls after non-waiting prompt submission and do not sweep another turn's artifacts. `EpicEngine.run()` in `src/engine/engine.ts` dispatches all delivery through a phase switch. `selectNext()` calls the coordinator; other activities do not consult it. `runtimeEvents()` persists display events but never feeds a coordinator inbox. `block()` and `persistBlockedState()` convert ordinary delivery failures into a stopped workflow.

The existing implementation result policy already rejects a result containing any failed test. The missing behavior in the browser-authentication example is recovery after that rejection, not detection of the contradiction. `src/engine/result-policy.ts` throws away the opportunity to converse by returning only an exception to the outer workflow.

Review permissions are weaker than README wording suggests. `CodexRuntime.threadOptions()` grants `workspace-write` to implementation and review; only the SDK coordinator gets `read-only`. `HerdrRuntime.createAgent()` grants `workspace-write` to all sandboxed roles. Both can grant full host access. Post-turn fingerprints detect many changes, but cannot prove authorship, prevent a transient edit, or make full host access a confined capability.

The originally inspected `@openai/codex-sdk` 0.151.0 exposes `runStreamed`, structured output, cancellation, command items with aggregate output, and completed-turn usage; the updated 0.153.4 adapter retains these contracts. Epicd initially dropped most of that information and now normalizes the available events. The SDK's public `Thread` interface has no method for injecting a message into an active turn. Queueing a message and interrupting before a follow-up are separate operations.

The 2026-09-06 model correction needs more than changing an example flag. `DEFAULT_AGENT_SETTINGS.orchestrator.model` is currently null, and `resolveAgentRoleSettings()` in `src/domain/types.ts` lets it inherit the run-wide model. `src/agent-options.ts` and the TUI can restore that inheritance. `HerdrRuntime.prepareNewSession()` copies requested settings into its effective contract and `createAgent()` omits `--model` when null. `ReasoningEffortSchema` and `cycleAgentReasoningEffort()` also expose a provider-wide set, not an Astra-specific capability check. These paths can otherwise undo the explicit orchestrator choice or select an unsupported effort.

Herdr CLI discovery succeeded from a managed pane. Its installed API schema reports protocol 20 and schema version 1, with lifecycle/output subscriptions, but no typed stream of Codex commands and their exit codes. `agent prompt --wait` waits for a settled lifecycle state, which can include a question or approval. It is not an acknowledgement that a particular Epicd turn completed. The current adapter only publishes `session.started`, then reads an atomic final-result file. `cleanOrphanedArtifacts()` deletes every result file under the run root, which becomes unsafe when different agents run concurrently.

The existing run schema has only one session per role and implicitly trusts persisted lifecycle fields as delivery proof. In particular, `closing` requires a candidate SHA but has no independent durable verification record. Adaptive capabilities need explicit proofs instead of relying on the path through the old phase switch.

Git linked worktrees have separate working files but share repository data and most refs. A worktree is useful workspace organization, not an independent authority boundary. This plan initially uses independent repositories with no shared writable object store, plus runtime confinement. This conclusion follows Git's documented sharing behavior: [git-worktree documentation](https://git-scm.com/docs/git-worktree).

## Decision Log

Decision: Persist the exact commit object content, approval reference, source/parent/tree, and I/O exclusion before writing; persist its Git-computed revision before object/ref effects. Retain it under a unique private `refs/epicd/commits/<commit-id>` ref without changing HEAD or the existing index. Rationale: a fixed object is recoverable without creating another commit or trusting staged content, and unverified revisions remain private. Author and committer are the explicit kernel identity `Epicd <epicd@epicd.local>`; the action's redacted single-line subject and a unique operation trailer are frozen in the intent. Date/author: 2026-09-07, Codex.

Decision: Treat a confirmed retained object as a physical fact, separate from exact verification and publication. If only an unretained object exists after confirmed I/O stop, preserve it and mark the intent failed with that explicit detail; recapture/review before a new commit rather than silently repeating the ref write. If I/O stop is unknown, preserve the exclusion even if no ref is visible. Rationale: filesystem state alone does not prove that an old controller cannot still write. Date/author: 2026-09-07, Codex.

Decision: Reserve independent review evidence and an inspection exclusion before source I/O, transfer ownership transactionally to a prepared reviewer turn, then reacquire inspection ownership only after confirmed process stop. Derive the report from that exact persisted turn, never from an action's supplied verdict. Rationale: before/after equality alone does not prevent transient writes, so physical read-only confinement and exact source inspections are both required. Cold recovery may discard an unrecorded verdict after stop; uncertain inspection I/O remains excluded. Date/author: 2026-09-07, Codex.

Decision: Preserve findings as immutable task records and store explicit independent resolution rationales in review evidence. New candidates reopen old findings for reassessment; reviewer replacement does not reset the ledger. Only valid accepted reviewer requirements become sticky, and their stage requirements merge with frozen policy rather than replacing it. Rationale: neither omitting a finding nor changing reviewers may erase a delivery obligation, but an invalid command ID must not permanently poison future plans. Date/author: 2026-09-07, Codex.

Decision: Use native managed `agent.start` with a private shell-replacing launcher function, then native `agent.prompt`; rotate the terminal after every settled turn while resuming the exact provider session. Rationale: managed readiness is a real Herdr contract, while removing the host-shell fallback prevents late model input from becoming a host command. Persist server socket identity and terminal handles separately from the conversation, prohibit terminal reuse across launch generations, and reconcile process stop through the outer supervisor even if Herdr has restarted. Date/author: 2026-09-07, Codex.

Rationale: neither a screen nor a generic JSON schema proves readiness, exact prompt acceptance, command outcomes, or process termination. ## Context and Orientation

Epicd is a TypeScript ESM CLI using Node.js 22.12+, Zod for data validation, `better-sqlite3` for local durable state, and Vitest for tests. `src/cli.tsx` constructs `EpicEngine`; `src/controller.ts` coordinates operator commands and headless execution; `src/tui/run-view.tsx` renders state. `src/status.ts` defines the existing version-1 JSON compatibility surface.

`src/engine/engine.ts` currently combines scheduling, prompts, agent sessions, Git/Beads effects, leases, error handling, and cleanup. Its useful boundaries include `claimCurrent()`, `implementCurrent()`, `reviewCurrent()`, `fixCurrent()`, `commitCurrent()`, `closeCurrent()`, `finalReview()`, `completeVerifiedEpic()`, `closeSatisfiedContainers()`, `runAgentTurn()`, and the cleanup/resume helpers. Extract the mechanics and guards; remove their automatic next-phase choices in adaptive mode.

`src/adapters/git.ts` owns fingerprints, temporary-index tree construction, staging, commits, and exact revision checks. `src/adapters/beads.ts` owns authoritative snapshots, atomic claims/adoption, closure, and sync. `src/adapters/store.ts` owns run identity, serialized state, events, leases, quarantine, and administrative writes. Existing ownership tokens protect database writes, not already-running external processes.

`src/adapters/runtime.ts` correlates SDK/Herdr session IDs and immutable model contracts. `src/adapters/codex.ts` wraps a persistent SDK thread; `src/adapters/herdr.ts` opens native agents in unfocused tabs and uses result files. `src/adapters/codex-process.ts` supplies specialized process supervision for runtime discovery, whereas `src/util/command.ts` does not currently prove termination of all descendants of arbitrary validation commands.

An **action** is a specific request such as starting a turn or committing a candidate. A **decision** is the orchestrator's short explanation plus one action. An **observation** is a recorded external event or measurement. A **candidate** is an immutable proposed application tree associated with a task and baseline. **Evidence** is a kernel-recorded observation of validation or independent review bound to that candidate. A **workspace generation** distinguishes a newly created checkout from one previously occupying the same role. **Reconciliation** means checking external state after an interruption before deciding whether an earlier action happened.

### Separate strategy, execution, and observation

Add `src/orchestrator/loop.ts` for the persistent decision loop, `src/orchestrator/context.ts` for bounded context assembly, and `src/orchestrator/prompt.ts` for its instructions. Add `src/kernel/actions.ts` for the discriminated action schema and dispatcher, `src/kernel/guards.ts` for shared admission checks, `src/kernel/reconcile.ts` for recovery, and `src/kernel/delivery.ts` for Git/Beads operations. Keep provider-specific details in adapters.

`EpicEngine` remains the CLI-facing facade during migration. Under its lease it starts the observation/scheduling machinery and invokes the loop. The kernel schedules admitted work and drains completed operations; it never synthesizes the next delivery action. On startup or resume it may reconcile already-authorized operations, stop a process, revoke evidence, and drain safe cleanup without asking the model. Those actions preserve existing commitments and constraints; they do not choose a delivery strategy.

Each loop iteration assembles the current task graph, delivery facts, admissible capabilities with denial reasons, outstanding findings, running agents, unconsumed observations, memory, and remaining budgets. The model returns one action. The kernel records the decision and admission outcome, executes or schedules it, and sends the result back. An agent-start action returns an operation handle promptly; the controller continues receiving events while that agent works. There is one orchestrator decision in flight and at most one active turn per agent instance.

Persist all relevant events; coalesce ordinary event wakeups over 250 ms and check running-operation health at least every 30 seconds. Safety enforcement does not wait for a model response. A detected protected-path mutation invalidates that operation's evidence and requests interruption immediately. Its diagnostic event wakes the orchestrator to choose recovery. File watchers are wakeup hints; snapshots taken before and after stopped operations are the authority. Never treat file-watch coverage as complete attribution.

An explicit `wait_for_events` action records an event cursor and optional deadline. Sleep without repeated model calls until new relevant evidence, user input, completion, or the deadline arrives. Memory changes, audit entries, and the orchestrator's own wait bookkeeping do not wake it recursively. A hung worker, a lost runtime connection, and elapsed time without output are observations with unknown causes, not proof of agent failure.

### Action API

Implement every action below as a narrow variant with Zod validation. Inspection actions can return bounded file ranges and artifact references; none exposes arbitrary SQL, unrestricted host shell, raw Git commands, or a setter for lifecycle state.

`inspect_run` returns authoritative delivery facts, graph/ownership observations with capture times, budgets, operations, and agents. `inspect_repo` reads paths, searches text, shows diffs/history, or lists files within a registered workspace or committed revision. `inspect_agent` returns assignment, turn status, capability flags, and available transcript evidence. `inspect_artifact` reads a bounded, redacted artifact range. `inspect_fixture` queries a declared fixture through a typed provider inspection.

The implemented delivery registry also supplies `inspect_candidate`, `inspect_validation_plan`, and `inspect_evidence` by run-scoped identities. Candidate inspection omits the full manifest, plan storage is bounded to 32 KiB, and evidence inspection bounds serialized diagnostics without exposing controller lease identity. The independent review registry adds `inspect_review`, character-paged `read_review`, and ledger-paged `inspect_findings`. An inspection preview may be shorter than the retained evidence row; it never upgrades truncated execution output to passing evidence.

`start_agent` starts implementation under a kernel-generated assignment contract. `create_implementation_workspace` first supplies a writable private copy at the frozen initial baseline (`baseCommitId: null` before any retained commit) or the latest retained private commit ID; it never resets another assignment. Independent review uses `run_review`, which fixes the candidate, plan, reviewer identity, phase, and evidence context; generic worker start/follow-up explicitly rejects review, verification, and final-review assignments. A verification workspace produces a fresh actual-SHA verification assignment rather than reusing the pre-commit conversation. Final epic review still needs an equally evidence-bound entrypoint. `start_specialist` starts a diagnostic agent using a named specialty and a settings role to inherit; it cannot grant that agent independent approval authority or a second implementation writer. Model-selected instructions supplement the kernel contract and cannot overwrite it.

`message_agent` adds a durable message to an agent mailbox and returns `queued` or an adapter-confirmed delivery state. It does not imply mid-turn delivery. `continue_agent` starts a generic worker's new turn only after the old one has stopped, carrying queued messages exactly once in the prompt envelope. A review follow-up uses `run_review` with the existing independent identity and the same candidate/workspace, supplying fresh kernel evidence and outstanding findings. `interrupt_agent` targets an exact turn and waits asynchronously for confirmed stop. `replace_agent` first revokes the old instance's result authority, then proves stop or quarantines its workspace before creating the new generation. Old results remain visible but cannot approve anything.

`define_validation_plan` binds the task's acceptance criteria and frozen mandatory checks to a plan and may add proposed checks. A plan change creates a new version and invalidates dependent eligibility until reevaluated. `capture_candidate` freezes the stopped implementation workspace into an immutable tree and a numbered candidate record. `create_review_workspace` materializes that candidate or an exact commit in a separate checkout. `restore_owned_delta` accepts a workspace ID, generation, baseline snapshot ID, and expected current fingerprint. Its initial implementation restores by regenerating a disposable workspace; it never accepts an arbitrary path or restores the user's checkout. `dispose_workspace` durably schedules deletion of a stopped, registered disposable workspace after required artifacts have been preserved.

`run_validation` starts a supervised command in a registered isolated workspace, using an argument vector, bounded working directory, declared environment bindings, timeout, and expected candidate. Its registered workspace chooses pre-commit versus exact-SHA phase; a check cannot borrow evidence from another phase or revision. There is no automatic fallback to unsandboxed host execution. `request_commit` currently creates the exact independently approved object and a private retention ref in its managed assignment repository, without changing HEAD or the existing index; `inspect_commit` exposes the durable intent and physical result. Publication must import that identical verified object into the canonical private delivery repository and then the user's repository. `request_publish` advances only this run's local delivery branch using an expected old ref value. `request_beads_transition` admits only `claim`, `adopt`, `close_task`, `close_container`, and `close_epic`, with operation-specific evidence. It does not expose arbitrary tracker updates.

`provision_declared_fixture` names an approved fixture definition and desired bounded operation. `change_agent_settings` selects only settings authorized for that role by frozen run policy. It rotates at a safe turn boundary and never mutates a running thread's contract. Changing the coordinator schedules its own replacement after the decision is durably accepted; it does not interrupt the very transaction requesting the change.

`record_memory` stores concise strategy, facts, hypotheses, failed approaches, or knowledge with evidence references. `wait_for_events` suspends the decision loop. `escalate` records a concrete question and the evidence or missing authority behind it; its use does not grant the requested authority. `complete_run` checks final delivery and tracker proofs before recording completion. There is no unrestricted `set_phase`, `mark_verified`, `ignore_failure`, or `execute_shell_on_host` action.

### Admission, ordering, and durable effects

Every mutation validates the current lease, control version, action's target IDs/generations, effective policy digest, relevant workspace/candidate identity, and current external preconditions. `controlVersion` increments on authoritative changes such as task ownership, candidate replacement, revocation, settings, or pause; it does not increment for every log fragment. An action based on a stale control version is rejected with fresh context. Inspection can read stale history explicitly, but that history cannot authorize a mutation.

Create an action intent and its audit event in one SQLite transaction before starting an external effect. Persist states `accepted`, `running`, `succeeded`, `failed`, `cancelled`, or `indeterminate`. Transition helpers require the lease and expected action state. Store the result, derived delivery state, evidence IDs, and completion event together. A unique `(run_id, decision_id)` plus a canonical request digest makes an identical replay return the recorded action; reusing that ID with different arguments is rejected. A deliberate retry gets a new action ID, a `retryOf` reference, and fresh guards.

SQLite and Git/Beads/processes do not share a transaction. Do not promise exactly-once execution. A crash after an effect but before recording success produces an indeterminate operation that must be reconciled. Agent creation has a persisted run/agent/turn identity before launch. Commit creation has a persisted parent, tree, and commit payload, so the same commit object can be recognized. Publishing uses ref compare-and-swap. Claims reconcile through authoritative owner/status. Closure records contain the task, verified revision, and expected transition. Fixture provisioning has a provider-owned resource identity and an inspect operation. Validation interrupted without a durable exit result is incomplete and must be rerun if policy permits.

Use a single logical scheduler for external mutations. An implementation writer owns its workspace until its process tree stops. Validation and review may run in separate candidate copies; review approval or commit creation for a task cannot race an implementation turn on that task. Fixture users hold a fixture-use record so provisioning or reset cannot race a test. Inspection and distinct diagnostic workspaces may run concurrently. Lease loss prohibits further effects, requests cancellation, and prevents late completions from becoming evidence. A new controller reconciles surviving workers before launching replacements. A database lease alone does not stop the old workers.

On a persistence failure, unsafe state, lost lease, or unknown ownership of a live process, stop affected work without consulting the model. Preserve uncertainty. Ordinary command failures, rejected actions, invalid model output, exhausted local attempts, and worker-runtime unavailability are typed problems fed to a healthy orchestrator while authority remains intact. A failed action is not a failed epic.

Coordinator-runtime failure requires a separate bounded execution rule: an unavailable Astra cannot diagnose its own unavailability. Normalize structured provider failures where supplied; distinguish retryable transport/rate/overload failures from authentication, model access, invalid configuration, and exhausted billing/quota. HTTP 429 alone does not establish retryability. Honor an available `Retry-After` without exceeding the run's waiting policy; never alter credentials, billing, or project limits automatically. Unknown native screen errors remain unclassified diagnostics, not invented API error codes. [Provider error distinctions](https://developers.openai.com/api/docs/guides/error-codes).

A provider safety-monitoring stop is a separate nonretryable condition. Preserve the notice, revoke the attempt's result authority, and request operator review; do not automatically create another session to continue the stopped task. Current Codex guidance says findings/resume availability differs by surface and that a CLI task can end without a resume flow. Runtime normalization must use an actual structured notice when available; absent that, preserve unknown diagnostics rather than asserting a safety classification from screen prose. [Safety monitoring and paused tasks](https://learn.chatgpt.com/docs/agent-approvals-security#safety-monitoring-and-paused-tasks).

For the first implementation, permit at most three transport attempts for one issued decision, with cancellable backoff starting at two seconds and capped at thirty seconds; a longer provider delay records a deadline instead of spinning. Persist attempt count and next eligible time before retry, maintain lease/worker health while waiting, and never replenish the allowance through restart or context rotation. Reuse the pending ticket only while its cursor, control version, policy, and coordinator generation remain valid. Retire a superseded attempt and reject its late response. One logical decision is charged once; record every transport attempt and any observed usage separately. Invalid structured model output still follows the existing bounded decision-feedback path.

On a nonretryable failure or exhausted transport allowance, record one runtime escalation without asking the unavailable model to produce it. Stop new delivery admissions, settle or interrupt existing workers under the pause contract, preserve findings/resources, and enter `awaiting_user` without switching model or legacy workflow. No task may be claimed before initial Astra preflight succeeds. This rule belongs in the decision-source/loop and durable journal integration in Milestones 2 and 4; it restores an execution dependency, not a deterministic delivery strategy.

The current implementation lives in `src/domain/decision-source.ts`, `src/adapters/decision-journal.ts`, and `OrchestratorLoop`. Database version 5 adds `decision_executions` and `decision_source_attempts`, including raw quarantine and pre-upgrade snapshot coverage. `prepare()` freezes a digest-checked context at most 64 KiB before `start()` commits a dispatch and its observation. `finish()` records a bounded/redacted outcome and deadline under the dispatching controller lease. Retries reuse that input even when new observations arrive; those observations remain unconsumed for the next decision. Control/policy changes invalidate dispatch, and cached decisions still pass normal action admission. A durable response can be replayed at the final decision-budget slot instead of incorrectly asking for another model call.

`DecisionSourceError` is a trusted adapter contract asserting a settled request, not an error classifier for model prose. Only its `transient` code permits an automatic retry. The default delays are two and four seconds for the remaining attempts; automatic backoff is capped at thirty seconds. A longer provider delay becomes a cancellable persisted deadline, up to a 24-hour harness bound; longer waits require operator direction. Unknown exceptions or controller loss leave an unsettled exclusion across tickets and restart. Independent health monitoring requests cancellation on lost authority even if the source promise does not settle. The controlled SDK source records generic but confirmed-stopped failures as nonretryable `runtime` failures; it does not classify embedded provider prose as an authentication, quota, safety, or transient code. Available normalized usage/events are journaled. Do not cast legacy generic SDK/Herdr exceptions into a settled-error type merely to enable retries.

Full epic/Beads context and native Herdr bootstrap remain subsequent work; these components are not a CLI entry point.

### Evidence and non-negotiable delivery prerequisites

A candidate record includes `candidateId`, generation, task ID, parent commit, full tree hash, application tree hash excluding `.beads`, workspace generation, capture manifest, policy digest, and validation-plan ID. Capture only after the writer stops. Record bytes and modes for tracked and eligible untracked application files, symlinks, deletions, and renames using NUL-delimited Git output. Reject unsupported submodules, LFS/filter materialization, or other layouts in preflight until their exact-copy contract is implemented and tested; do not silently omit content. Use Git object IDs as opaque strings, not fixed 40-character assumptions.

A validation plan contains named required checks and acceptance criteria from the frozen repository declaration, the task, and independently raised findings. Kernel-enforced required checks come from explicit structured policy. The orchestrator can add checks; it cannot remove or weaken required checks or substitute `true` for a required command. Free-form acceptance criteria still require reviewer judgment: the kernel can prove that specified checks ran against specified bytes, not that arbitrary business requirements have been mathematically proven.

Where no repository check declaration exists, the orchestrator proposes a nonempty plan from repository instructions and task criteria, and an independent reviewer must accept its adequacy before approval can be issued. This remains a judgment-based coverage check, visibly distinguished from operator-declared mandatory commands. Reviewer-requested additions become requirements in the next plan version. The kernel must not manufacture a meaningful-test guarantee from a command name or a successful exit code.

Agent reports are claims. `ImplementationResultSchema` and `ReviewResultSchema` remain useful input formats, but reported `tests` alone cannot mint passing validation evidence. `ValidationEvidence` records the kernel-launched command/check ID, command digest, actual exit status, start/end times, workspace/candidate identity, relevant environment/fixture generation, and output artifact references. Missing, failed, cancelled, skipped-required, truncated beyond interpretable output, and unknown results never satisfy a required check. A later retry can supersede a specific failed check with a pass for the same required check and current environment; history is retained. A new failed result revokes eligibility until resolved.

`ReviewEvidence` identifies the reviewing agent and turn, candidate generation, base and tree, result, findings, and validation references. A reviewer cannot have served as an implementer or repair writer for this task. Do not give a fresh reviewer the implementer's private conversation or another reviewer's verdict as an instruction to approve. Give it the task, repository instructions, factual evidence, diff, and relevant prior findings for targeted repair review. Replacements inherit unresolved findings, so replacing a reviewer cannot erase them. The kernel preserves the finding ledger; resolution requires suitable independent review evidence, not the coordinator deleting an array.

Committing requires a current independent approval, all required pre-commit checks, no unresolved findings, a stopped writer, and the exact approved full tree/parent. Use a temporary index and inspect its tree; never trust arbitrary staging left by an agent. Post-commit verification uses a fresh agent at the actual candidate commit SHA, with its own required validation evidence. A synthetic snapshot used for pre-commit review is explicitly labeled as such and cannot count as exact-commit verification. Post-commit fixes produce a new candidate and follow-up commit; no automatic amend or history rewriting.

Publishing requires current exact-commit verification and imports the identical object, preserving its SHA. Closing a task additionally requires that published verified revision, fresh Beads ownership and dependency checks, and no superseding candidate or unresolved mandatory finding. Once tracker-only commits advance the delivery branch, closure retry validates the recorded verified application tree and a proven tracker-only descendant chain; it does not require current HEAD to equal the earlier application commit. This is necessary for a crash after tracker sync or a tracker commit.

The final epic review examines the exact published application state after all concrete descendants are closed. Root closure requires fresh graph evidence that no new open descendant appeared, no unresolved epic finding, and an independent final verification record. Nested containers close only after their actual descendants. If final review finds a regression in an already-closed task, the orchestrator can start an epic-scoped repair assignment tied to that finding, bounded by the epic repair budget; publish a reviewed and verified follow-up commit and rerun final review. The root stays open. This supports recovery without silently inventing tracker issues or reopening user-managed tasks.

### Workspace isolation and safe recovery

Add `src/adapters/workspaces.ts` with kernel-owned workspace manifests under the private Epicd state directory. A manifest records run ID, workspace ID/generation, canonical path, purpose, baseline, owner agent/turn, lifecycle, and cleanup state. Use independently initialized or copied Git repositories with no object alternates, writable hard links, inherited remotes, executable hooks, or copied credentials. Keep read-only history needed for review. The kernel can export/import Git objects over local supervised commands; agents receive no writable path to the authoritative repository or another workspace.

Kernel Git commands use controlled configuration and environment so inherited hooks, external diff programs, credential helpers, or checkout filters cannot turn metadata operations into unrestricted repository execution. Required repository hook checks must be represented as explicit confined validation, not silently omitted. Dependency installation and build preparation are also explicit workspace operations: use the candidate's lockfiles, declared cache/scratch paths, and authorized network policy. Do not assume that copying tracked files also supplies ignored dependencies, browser binaries, environment files, or generated assets. Preparation that changes candidate source requires recapture and fresh review.

Maintain one private delivery repository. An implementation agent receives its working files under a confined profile; Git metadata, frozen policy/instruction control files, and authoritative tracker/state storage are protected. Review/verification agents receive separate copies, with mutable build/scratch output but immutable candidate source. Commands that try to append tracked receipts should fail at the source boundary; if an adapter can only detect such a change, that attempt is ineligible for approval and its workspace is quarantined. Do not describe post-hoc detection as prevention. Runtime capability admission distinguishes these protections.

For the initial release, require source immutability during accepted review/verification, not merely equality before and after: a verifier could edit a test, run it, and restore it. If a test tool requires a tracked-path write, run it as diagnostic work in a disposable mutable copy, then rerun an equivalent approved validation that preserves candidate source before accepting evidence. The selected repository remains the source of the initial baseline and the live Beads database. Local delivery uses a run-owned branch that is never checked out by Epicd. Tracker operations may update `.beads` through its authoritative adapter as already authorized by starting a run; tracker-only objects on the delivery branch are constructed with an isolated index and cannot stage unrelated user changes.

`restore_owned_delta` is legal only in a disposable managed workspace with a known generation, a complete baseline, a stopped process tree, and no detected user intervention. Fingerprints establish expected bytes; confinement plus exclusive workspace ownership establishes the scope that may be replaced. A changed canonical checkout, a managed tab that the user took over, or unknown writers is an ownership problem requiring preservation and user direction. On ambiguous provenance preserve the whole workspace. For known disposable scratch, preserve redacted receipt/output artifacts first, then regenerate the copy from the immutable candidate.

Workspace deletion is a durable cleanup operation. Validate canonical paths and manifests, refuse symlink escapes and unregistered directories, and never delete while a process may still write. Do not reuse workspace IDs or paths for a new generation. Cleanup failure after delivery leaves a complete, non-owning run with reachable cleanup intent, matching the existing product's behavior.

## Idempotence and Recovery

The same persisted decision submitted twice returns the same action result. An action whose effect may have happened is reconciled before retry. Ref updates compare the expected previous value; tracker transitions reread authority; workspace/agent generations never get reused; fixture ownership must be externally provable. No retry can waive an evidence requirement or refill its own budget.

On resume, acquire the lease, validate/migrate the state, load effective policy, inspect live workers and resource intents, reconcile indeterminate effects, invalidate superseded evidence, restore the last committed observation cursor and memory, then permit new decisions. Cleanup-only resume skips model initialization where unnecessary, preserving the existing SDK cleanup behavior. If persistence is unavailable, stop admitting work and preserve resources; an LLM is not a database repair mechanism.

Review recovery must not rerun an already dispatched review action. A finished evidence row and its immutable findings survive replay; a bound but unfinished turn needs exact process-stop reconciliation and discard of the unrecorded verdict. An admission or post-review inspection with unknown I/O still owns its workspace, including after controller lease replacement. Do not mark that operation stopped from a fingerprint comparison or from the absence of an agent process; it represents controller-owned I/O, not only the reviewer. New candidate generations invalidate approval and require independent reassessment of prior findings. Accepted required commands survive that regeneration.

Private commit recovery begins with its durable operation, raw object content, planned revision, and source I/O exclusion. `reconcileCommit()` refuses Git-only reconciliation until that exclusion has independent stop evidence; a new lease or absent ref is not stop proof. Once I/O is stopped, compare the exact object bytes and unique private ref. Record a retained matching object without rewriting it, record an absent/unretained result with explicit details while preserving any object, and preserve conflicts for investigation. New model requests cannot create a second commit for that candidate. New implementation work must use the latest retained private parent; after publication/tracker integration this must include the proven tracker-only delivery tip. There is no automatic amend, reset, or deletion of a user's checkout or an older assignment.

Back up the local SQLite database with SQLite's backup facility before the forward-only migration; copying only the main file while WAL writes are active is not a backup procedure. A downgrade must not open and rewrite V2 state. Existing Git/Beads effects cannot be undone by restoring SQLite alone. For rollback during development retain the legacy mode and use fresh disposable test state; for a real run keep the newer reader available to inspect pending external obligations.

Deletion and fixture cleanup are limited to explicitly recorded owned resources. Published local delivery branches are retained after successful cleanup. Quarantine or cleanup abandonment preserves forensic metadata and warns that external resources may remain; neither operation authorizes deleting unrelated directories, closing unrelated Herdr tabs, or dropping a database whose owner cannot be proved.
